12 / Persistent records

Closing the programme
doesn't erase the history.

In-memory state

Vehicles · Slots · Sessions

Dynamic arrays hold registrations, current occupancy and completed parking visits.

Binary `.dat` file

Versioned header, fixed-width fields, stable IDs and no raw pointers.

Recovery design

Validate before accepting

Loading checks record counts, types, references and consistency before replacing the current state.

Write safely

Save to a temporary file and replace the target only after successful writing.

Verified uploaded version: records are saved on normal exit; a crash before saving may lose recent in-memory changes.

13 / Software architecture

Small modules.
Clear responsibilities.

Codes/ main.c // menus + input parking.c // rules + sessions registration.c // input validation storage.c // binary persistence Header Files/ parking.h // types + API registration.h // validation API tests/ test_parking_system.c

Separation of concerns

Console interaction does not need to know the binary file layout. Storage does not decide who is eligible to park. Parking logic owns allocation and billing.

Multiple translation units compile and link into one executable through the Makefile.

14 / Engineering in C

Fundamentals used
for real reasons.

Structures + enums

Represent vehicles, parking bays, sessions, categories and status codes.

Dynamic memory

calloc, realloc and free support growing records and cleanup.

File handling

fopen, fread, fwrite and rename preserve state.

Time calculations

time_t and elapsed-time arithmetic determine parking duration.

String handling

Validation, normalisation, duplicate checks and bounded input.

Modular compilation

Headers declare APIs; linked C files provide implementations.

15 / Reliability

Correctness is a feature.
Not an afterthought.

Duplicate preventionNo duplicate registration or active parking session.
Capacity checksNo second vehicle in an occupied bay.
Memory checksBounded allocation growth and cleanup paths.
Persistence validationReject inconsistent or corrupted binary records.
Regression testingRegistration, billing, entry/exit, restart and failure cases.
Explicit limitationsA software prototype, not a physical parking-control installation.

With this software
